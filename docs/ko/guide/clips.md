# 구간 클립과 GIF

## 왜 자르나

Sentry는 에러가 몇 초 지점에서 났는지 알려줍니다. 티켓에 들어가야 하는 건 그 앞뒤 30초지 세션 전체가 아닙니다. 자르는 건 변환 시간에 대한 답이기도 합니다. 변환은 실시간 재생이라 1시간짜리는 4배속으로도 분 단위가 걸리지만, 30초는 초 단위에 끝납니다.

```bash
npx tapelay replay.json --from 4:20 --to 4:50
```

`--from`과 `--to`는 초, `m:ss`, `h:mm:ss`를 받습니다. `--to`를 생략하면 세션 끝까지입니다.

## GIF

```bash
npx tapelay replay.json bug.gif --gif --from 4:20 --to 4:50
```

GIF는 Jira와 Slack에서 인라인으로 보이는데, 사실 그게 핵심인 경우가 많습니다. 대신 금방 커지기 때문에 CLI는 2분, GUI는 90초를 넘는 구간을 거부합니다.

GIF는 256색 포맷이라 그냥 인코딩하면 UI 글자가 뭉개집니다. 그래서 `palettegen`을 `stats_mode=diff`로 돌려 클립 자체에서 팔레트를 만들고, 실제로 움직이는 영역에 색을 몰아줍니다. 화면 대부분이 정지인 세션 리플레이에 잘 맞는 방식입니다.

| 옵션 | 기본 | 설명 |
|---|---|---|
| `--gif-fps <n>` | `10` | 프레임 레이트. |
| `--gif-width <n>` | `800` | 가로 픽셀. 세로는 비율대로 따라갑니다. |

## 한 가지 주의점

rrweb은 FullSnapshot에서만 재생을 시작할 수 있습니다. 그래서 클립은 시작 지점 **직전** 스냅샷부터 렌더한 뒤 잘라냅니다. 변환 비용은 클립 길이가 아니라 그 스냅샷까지의 거리에 비례합니다. Sentry는 스냅샷을 자주 남기는 편이라 보통은 크지 않습니다.
